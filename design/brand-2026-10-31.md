# Brand · tudo o que o cliente informou, num lugar, editável: spec de UX/UI
Data: 2026-10-31 · Status: **proposta, aguarda o OK do Gusta** · Dono: maquina-design
Mockup: `design/mockup-brand.html` (não publicado). Barra "Prototype": Desktop / Phone 390; qualquer "Edit"/"Add" abre o campo no lugar e "Save" grava (toast "Saved"). Dados são exemplo.
Pedido do Gusta 31/10: "faltou a tela Brand que mostra tudo que ele preencheu no wizard, lá ele vai poder editar também".

## 1. Problema
O que o onboarding coleta (negócio, oferta, público, metas, Meta) fica espalhado: parte só existe dentro do wizard ("Revisit setup"), parte em Offers, parte em Settings. O `/brain` virou o grafo 3D, que mostra mas não edita. Falta um lugar pra **revisar e corrigir** o que o site/Eddy preencheu.

## 2. Decisões e porquê
1. **Navegação: a Brand é a porta de entrada do "Brain" (recomendado).** O item "Brain" da sidebar abre `/brain` com duas abas: **Brand** (padrão, editável) e **Map** (o grafo 3D de hoje, só leitura). Por quê: é a mesma coisa (o que o HookMill sabe do cliente) vista de dois jeitos; dois itens na sidebar repetiriam o "Revisit setup no Brain" de 21/10 e o % do Cérebro em dois lugares. A Home já mostra o Map no palco e linka "View brand" pra cá. Alternativa: item próprio "Brand" na sidebar e o Brain fica só o 3D.
2. **"Revisit setup" sai.** Editar o setup = editar a Brand. O wizard (ou o Eddy) não reabre pra correção; só pra preencher lacunas ("Fill the gaps with Eddy", §2.7).
3. **Linhas rótulo/valor, edição no lugar, salva por campo.** Cada linha mostra o valor; "Edit" troca pelo campo + Save/Cancel (Enter salva, Esc cancela). Salvar manda **só aquele campo** (`PATCH` parcial). Por quê: é o padrão de settings de SaaS (Vercel/Linear), não tem botão "Save all" esquecido e cada erro aparece na linha certa. O cabeçalho do cartão mostra "Saved just now" / "Saved Oct 30".
4. **Sem etiquetas de origem** ("from your site") — o Gusta pediu pra tirar. O que veio do site aparece como valor normal.
5. **Campo vazio aparece, em âmbar, "Missing"**, com "Add" no lugar de "Edit". Nada some por estar vazio.
6. **Seções, nesta ordem:** Business · Offer · Audience · Brand kit · Meta (com Publish templates). Offer tem seletor de ofertas no topo (chips) + "Add offer"; **Audience segue a oferta escolhida** e diz "for Weighted blanket", porque no modelo de dados público, dores e notas são campos da oferta (`OfferBrief`).
7. **Coluna direita fixa (sticky):** anel do % do Cérebro ("12 of 13 things known"), o que falta com link pra linha, índice das seções com ponto de estado (verde completa, âmbar parcial, vazio) e **"Fill the gaps with Eddy · Start"**: abre o onboarding conversacional em modo "só o que falta" (pergunta só os itens vazios). É assim que Eddy e Brand conversam: **o Eddy preenche, a Brand é onde se revisa**; tudo que o Eddy confirma cai aqui, e daqui o Eddy é chamado só pras lacunas.
8. **Meta e templates são só leitura aqui.** Mostra conta, act_, moeda, Página e templates com "Manage in Settings" / "Open". Conectar/trocar mora em Settings › Connections (decisão 6 do onboarding-v2: um lugar pra cada coisa).
9. **"Read the site again"** no cabeçalho: roda a leitura de novo e **preenche só campos vazios** (mesma regra de hoje, `applyMutate`), com toast "Filled 2 empty fields". Nunca sobrescreve o que a pessoa editou.
10. **Sem lima nesta tela.** Não há "avançar"; o botão de salvar é tinta. O lima fica pro palco/Home.

## 3. Campos e onde cada um salva
| Seção | Campo | Controle | Salva em |
|---|---|---|---|
| Business | Website | `Input` url | `PATCH /workspace {websiteUrl}` |
| | Name | `Input` | `PATCH /workspace {name}` |
| | Code | `Input` mono, 2–4 letras | `PATCH /workspace {shortCode}` (409 se em uso → erro na linha) |
| | Industry / Market | `Input` | `PATCH /workspace {industry}` / `{market}` |
| | Language | `Select` EN / PT-BR | `PATCH /workspace {uiLocale}` |
| | Brand color | `BrandColorField` existente | `PATCH /workspace {brandColor}` |
| | What counts as a result | chips (`RadioGroup`) + "More…" + Other | `PATCH /workspace {resultType, resultTypeOther}` |
| | Target cost per result | moeda + min + max | `PATCH /workspace {targetCpa:{min,max,currency}}` (400 `min_lte_max` → erro na linha) |
| | Monthly spend cap | `Input` numérico | `PATCH /workspace {monthlySpendCapUsd}` |
| Offer | Name (chip), What it is, Promise, Offer and price, Call to action, Proof | `Textarea`/`Input` | `PATCH /offers/:id {name|what|promise|offerAndPrice|cta|proof}` |
| | Landing page | `Input` url | `PATCH /offers/:id {sourceUrl}` (**confirmar com o arquiteto** se `sourceUrl` é editável no `UpdateOfferBody`) |
| | Add offer | abre a leitura de URL ou formulário curto | `POST /offers` |
| Audience | Who it's for, Pains, Instructions | `Textarea` | `PATCH /offers/:id {audience|pains|notes}` |
| Brand kit | Logo (Replace/Remove), Brand files, Product demo videos (upload com progresso, Remove) | `Dropzone` + `Progress` | `kit-marca-v1` (em construção): upload via `POST /uploads` com finalidade nova → `complete` → vincular ao kit; `DELETE` pra remover |
| Meta | conta, Página | só leitura | `GET /meta/connection` |
| | Publish templates | link | `/settings/connections/templates` (existe) |
O % e o "Missing" usam `brainCompleteness(ws, offers)` (`web/src/lib/brain.ts`), a mesma função da Home e do onboarding.

## 4. Componentes
| Peça | shadcn / próprio |
|---|---|
| Abas Brand / Map | `Tabs` (`/brain?view=map` pro Map, pra link direto) |
| Linha editável | próprio `FieldRow {label, hint?, value, empty?, editor, onSave}`; `Button` ghost "Edit"; `Input`/`Textarea`/`Select`; erro = `text-status-failed text-xs` com `aria-describedby` |
| Seletor de oferta | `ToggleGroup type="single"` + `Button` outline tracejado "Add offer" |
| Kit | `Card` + `Dropzone` próprio (o do Iterate) + `Progress` + `AlertDialog` no Remove |
| Meta | `Card` só leitura |
| Coluna direita | `Card` + anel (o do Brain de hoje) + `nav` com âncoras |
| Toast | `sonner` ("Saved", "Couldn't save. Try again.") |

## 5. Estados
| Estado | Comportamento |
|---|---|
| Carregando | skeleton das linhas dentro de cada cartão, com títulos reais |
| Salvando um campo | Save vira spinner, campo travado; sucesso → linha volta ao valor + "Saved just now" |
| Erro ao salvar | linha continua em edição, mensagem embaixo do campo (ex.: "Code MCL is already used by another client") |
| Sem oferta | Offer e Audience mostram "No offer yet" + "Add offer" |
| Sem Meta | cartão Meta com "Not connected" + "Connect in Settings" (azul da Meta só no botão de Settings) |
| Kit vazio | 3 zonas tracejadas: Logo, Brand files, Demo videos |
| Upload em curso | linha com barra azul e "Cancel"; dá pra sair da tela, continua |
| Lendo o site de novo | botão "Reading…" com checklist num `Popover`; ao fim, toast com quantos campos preencheu |
| CLIENT / MEMBER sem permissão | tudo visível, sem "Edit"/"Add"/upload; chip "View only" no título |

## 6. Responsivo (390 no mockup)
- Coluna direita sobe pro topo (anel + o que falta); o índice vira **faixa de chips com ponto de estado, fixa no topo** ao rolar.
- Linha: rótulo em cima, valor embaixo, "Edit" à direita; o editor ocupa a largura toda.
- Kit em uma coluna; logo 160 px.
- Todos os alvos de toque ≥ 44 px, exceto os botões `sm` em linha (36 px) com área de toque estendida.

## 7. Aceite
- Todo campo do onboarding (negócio, oferta, público, metas) aparece aqui e salva com um `PATCH` só daquele campo; recarregar mostra o valor salvo.
- Nenhuma etiqueta de origem na tela.
- O % e a lista do que falta batem com a Home e com o fim do onboarding (mesma função).
- "Read the site again" não sobrescreve campo preenchido.
- Em 390 px nada estoura; editar um campo de texto longo não empurra a página pra lado.
- "Revisit setup" não existe mais em lugar nenhum.

## 8. Decisões pro Gusta
1. **Brand como aba padrão do Brain, com o 3D na aba Map** (recomendo) ou item "Brand" próprio na sidebar?
2. **Salvar por campo** (recomendo) ou um "Save" por seção?
3. Tirar o "Revisit setup" e usar só "Fill the gaps with Eddy" pras lacunas: ok?
