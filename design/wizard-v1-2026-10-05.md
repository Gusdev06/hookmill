# Home + wizard do criativo (v1): spec de UX/UI
Data: 2026-10-05 · Status: **mockup aguardando aprovação do Gusta** (nada vira código antes disso)
Mockup navegável: https://claude.ai/artifact/N271PVVM6NiKRAdBHM17YV · fonte: `projects/maquina-anuncios/design/mockup-wizard-v1.html` (atualizar SEMPRE este arquivo, pra o link não mudar)
Fontes: `projects/maquina-anuncios/time/briefing-ux-ui.md`, `brainstorms/2026-10-05-maquina-anuncios-estrutura.md`

> Os dados do mockup (ofertas Orbit Budget / Quiet Mind 21 / Brightside Kit, custos, tempos) são **exemplo fictício**. Os custos por motor em especial são placeholders: a API devolve o valor real.

## 1. Problema
O clonador foi rejeitado por ser um "frankenstein": cada tela com uma lógica, chat no meio, sem cara de SaaS. A v1 precisa levar a pessoa de um briefing até um vídeo aprovado em 7 etapas, sendo que duas delas (geração e render) levam minutos. O risco de UX é duplo: a pessoa se perder no meio do fluxo e ficar olhando um spinner sem saber se algo está acontecendo.

## 2. Decisões e porquê
1. **Molde = dashboard da Vercel.** Header com breadcrumb (logo / workspace / criativo) + abas Home, Offers, Library, Settings. A Home é a "lista de deploys": uma linha por criativo, com etapa + status colorido, motor, tempo e autor. Quem usa Vercel lê a tela sem aprender nada.
2. **"Waiting on you" no topo da Home.** Reúne o que depende de uma pessoa: vídeo pronto pra revisar, roteiros pra escolher e cena que falhou. Erro entra aqui porque também pede ação.
3. **Wizard com trilho lateral de etapas** (desktop) e **barra compacta "Step 3 of 7" + 7 segmentos** (mobile, toque abre a lista). A pessoa pode voltar a qualquer etapa já feita. O nome do criativo é editável no trilho.
4. **Barra de ação fixa no rodapé** em todas as etapas: Back + ação primária ("Continue to X", "Generate"). Do lado esquerdo, uma dica de estado ("Script A selected · 27s"). No mobile ela é fixa na base da tela e os botões ocupam a largura toda.
5. **Espera honesta = checklist da etapa real + progresso + "pode sair".** Roteiros: orb + checklist (leu o brief, estudou os vencedores, escrevendo o B) + o roteiro aparecendo em streaming. Rostos: efeito Image Generation em cada tile + tempo decorrido. Geração: barra geral, ETA e Border Beam só na cena que está gerando. Render: % + frame X de 810 + checklist. Os efeitos do libraries.dev aparecem **só** nesses estados.
6. **Custo aparece uma vez, na etapa Engine** (estimativa por motor + resumo), e depois só como fato na revisão final. Nenhum botão leva custo (o Gusta recusou isso no briefing).
7. **Sem chat.** "Request changes" é uma lista fechada de 4 caminhos, cada um voltando pra etapa certa e dizendo o custo do retrabalho: refazer uma cena (só ela regera), legenda/headline/CTA (volta pro Edit, sem geração), reescrever uma fala (regera a cena da fala), outro rosto (regera tudo). Tem um campo de nota opcional, que fica como comentário e não é conversa.
8. **Vídeo protagonista.** Na revisão final o player ocupa a tela (palco preto, 9:16, até 72vh) e só embaixo dele vêm o nome, os fatos e os dois botões. No Edit, o player fica à esquerda e o painel de template à direita, com 340 px.
9. **Memória de vencedores visível.** A etapa Scripts diz quais vencedores da oferta foram usados ("Informed by 2 winners…"). A Library tem o botão de marcar vencedor e explica pra que ele serve.
10. **Tema escuro único**, sem tema claro na v1 (briefing, Q2 "a").

## 3. Tokens
Fonte **Geist** (UI) e **Geist Mono** (timecode, custo, IDs, rótulos de etapa). No Next: `geist` via `next/font`; no Tailwind v4, use nomes literais no `@theme inline` (ver a pegadinha do shadcn: `--font-sans: "Geist", …`).

| Token | Valor | Uso |
|---|---|---|
| `--bg` | `#0a0a0a` | fundo da página |
| `--surface` | `#111111` | cards, linhas, painéis |
| `--surface-2` | `#171717` | inputs, bloco do gancho, item ativo |
| `--hover` | `#1f1f1f` | hover de linha e botão |
| `--line` | `#262626` | todas as bordas de 1px |
| `--line-2` | `#3a3a3a` | borda no hover / forte |
| `--fg` / `--fg-2` / `--fg-3` | `#ededed` / `#a1a1a1` / `#878787` | texto primário / secundário / terciário |
| `--btn` / `--btn-fg` | `#ededed` / `#0a0a0a` | botão primário (branco, à moda Vercel) |
| `--blue` | `#52a8ff` | em andamento (gerando, renderizando) |
| `--amber` | `#f2a33a` | espera ação humana; vencedor |
| `--red` | `#ff6166` | falhou |
| `--green` | `#62c073` | pronto / aprovado |
| cada status | `rgba(cor, .12)` | fundo de tag/banner |
| `--stage` | `#000` | palco do player |
| raio | 6 px controles · 8 px cards · 12 px palco/vazio | |

Não existe cor de destaque de marca: a cor aparece só pra indicar status, e o primário é branco. Nada de gradiente roxo, emoji ou brilho. Tamanhos de tipo: 24 (h1), 16 (h2), 14 (base), 13 (secundário), 12/11 mono (rótulos). Rótulo de etapa = mono 11 px, caixa alta, `letter-spacing .06em`.

shadcn: `style new-york`, `baseColor neutral`, `--radius: 0.5rem`. Mapeie `--background`→`--bg`, `--card`→`--surface`, `--muted`→`--surface-2`, `--border`/`--input`→`--line`, `--primary`→`--btn`, `--destructive`→`--red`, `--ring`→`--blue`. Os status entram como `--color-status-*`.

| Botões | `Button` | `default` (branco), `outline` (padrão), `ghost`, tamanhos `sm`(28) / `default`(32) / `lg`(40) |

| Status | `Badge` customizado `StatusChip` (ponto + texto) | `progress` com ponto pulsando, `waiting`, `failed`, `approved`, `draft` |

| Cards "Waiting on you" | `Card` | miniatura 9:16 + chip + CTA |
| Oferta / motor / rosto / mudança | `RadioGroup` com itens em card (`RadioGroupItem` + label de bloco) | selecionado = borda `fg` |
| Briefing | `Form` + `Input` + `Textarea` + `Label` | tag tracejada "From page" no campo que a IA preencheu |
| Banners | `Alert` | `destructive` pro erro; padrão pro info |
| Skeletons | `Skeleton` | Home e briefing carregando |
| Progresso | `Progress` | azul em andamento, verde quando completo |
| Switch | `Switch` | end card, "Winners only" |
| Voz | `Select` | + botão "Hear" |
| Etapas mobile | `Collapsible` (ou `Sheet` lado de baixo se crescer) | |
| Toast | `Sonner` | "Approved. Saved to Library.", "Generation started…" |

| Espera | libraries.dev: `ThinkingOrbs` (Scripts), `ImageGeneration` (Avatar, miniatura da cena gerando), `BorderBeam` (cena em geração) | nunca fora de estado de espera; respeitar `prefers-reduced-motion` |

## 5. Telas e estados
O mockup tem uma barra "Prototype · State" no topo pra alternar os estados de cada tela. Ela não faz parte do produto.

### Home `/`
- **Ready:** h1 "Creatives" + contagem, busca, "New creative". Seção "Waiting on you" (3 colunas desktop / 1 mobile). "All creatives" com filtro All / In progress / Needs you / Approved e as linhas. Linha em andamento mostra a mini barra de progresso.
- **Empty (primeiro uso):** caixa tracejada com as 7 etapas, "New creative" e "Add an offer first".
- **Loading:** skeleton das 3 cards e de 6 linhas, com o mesmo layout.
- **Error:** `Alert` destrutivo ("The server didn't answer in 10 seconds. Showing the list from 3 minutes ago." + Retry) acima da lista em cache.
- Clique numa linha abre o wizard **na etapa atual** daquele criativo.

### Wizard `/creatives/:id/:step`
Trilho: nome editável, oferta + idioma, 7 etapas (feito = check branco; atual = contorno; em andamento = anel azul girando; falhou = "!" vermelho) e um resumo (script, rosto, motor, "Saved just now"). Autosave em todo campo.

1. **Offer.** Duas abas: *Existing offer* (radio com idioma e nº de vencedores) / *New from link*. Estados: link vazio → lendo (checklist: buscou a página, extraindo, detectando idioma; campos em skeleton) → preenchido (todos os campos editáveis, tag "From page") → erro (HTTP 403: colar o texto da página ou preencher à mão). O botão Continue só habilita com uma oferta escolhida ou preenchida. Uma oferta nova é salva em Offers ao continuar.
2. **Scripts.** 3 a 5 cards (2 colunas desktop / 1 mobile). Cada card: "Script A", tag do ângulo, duração, **gancho em destaque** (17 px semibold em bloco próprio), blocos com timecode mono (Problem / Product / CTA) e as ações Edit (vira textarea inline, Save/Cancel), Regenerate (só aquele) e Use this script. "Regenerate all" no topo. Estados: escrevendo (orb + checklist + streaming + skeletons), pronto, **parcial** (rate limit: os 2 prontos ficam visíveis + "Write the other 2").
3. **Avatar.** Descrição editável de quem aparece + "Generate 4 new faces". Grade 4 colunas (2 no mobile), 4:5, selecionado com anel branco e check. Estados: gerando (efeito por tile + tempo decorrido + "20 to 40 seconds"), pronto, erro (bloqueio de segurança: explica a causa provável e mantém os rostos anteriores esmaecidos).
4. **Engine.** Dois cards de rádio: *Scenes (Kling 3.0 / Seedance)*, com seletor de modelo, e *Avatar + voice + lipsync*, com seletor de voz e "Hear". Cada card tem uma linha de trade-off e estimativa de custo, tempo e nº de cenas. O nº de cenas é sempre o `sceneCount` que a API devolve, nunca um valor fixo. No lipsync são **um clipe por bloco do roteiro** (3 a 5 num roteiro de 25 a 30 s), e na Geração eles aparecem como cenas, igual ao Kling/Seedance (decisão de 05/10). Formato 9:16 / 4:5 / 1:1. Resumo à direita (embaixo no mobile) com custo estimado e gasto do mês vs. teto. Primário: **Generate**.
5. **Generation.** Painel com título real ("Generating · 2 of 4 scenes ready"), ETA, barra e o aviso "You can close this page…". Lista de cenas: miniatura, rótulo + timecode, a fala, o prompt visual (mono), o status e a ação. Estados por cena: Ready (Regenerate), Generating (beam + %), Queued, Failed (motivo em vermelho + "Regenerate scene"). Estados de tela: em andamento, cena falhou, tudo pronto. "Continue to Edit" só habilita com tudo pronto.
6. **Edit.** Player à esquerda e painel à direita: template (Clean / Bold captions / Headline + captions, com miniatura), estilo da legenda (Word by word / Full line / Off), posição, headline (se o template tiver), texto do CTA e end card. Ao mexer num campo aparece "Changes not in the preview yet" e o Render vira primário. Estados: pronto, **renderizando** (overlay no player: %, frame X de N, checklist), erro (frame 388, arquivo incompleto: "Render again").
7. **Final OK.** Player grande e mais nada competindo com ele. Embaixo: nome, fatos (oferta, script, rosto, motor, 0:27, formato, custo) e **Request changes / Approve**. Request changes abre um painel inline com os 4 caminhos + nota → "Send back to <etapa>". Approve leva pra Library com o item novo destacado e um toast.

### Offers `/offers`
Lista de ofertas em radio-cards + briefing da selecionada, editável ("Re-read page", "Save brief"). Empty: campo de link + "Read page".

### Library `/library`
Grade de miniaturas 9:16 (2 colunas no mobile). Filtro por oferta, switch "Winners only" e estrela pra marcar vencedor (âmbar + selo "Winner"). Item recém-aprovado tem anel verde + selo "New". Empty explica como algo chega ali.

### Settings `/settings`
Workspace (nome, idioma da interface), Members (Gusta owner, Tordan member, Invite), Connected services (Anthropic, WaveSpeed, chave mascarada), Spend (mês, teto). Por enquanto é só o destino; não está completa.

## 6. Responsivo
- Breakpoints: **≤900 px**, grades de 3/2 colunas viram 1 e Engine/Edit/Offers empilham; **≤760 px**, o trilho some e entra a barra "Step N of 7" fixa sob o header, a barra de ação fica fixa na base (com `safe-area-inset-bottom`), a lista vira linhas empilhadas (nome → etapa + status → tempo + autor) e as abas globais rolam na horizontal.
- Gutter: `clamp(16px, 3vw, 24px)`. Nada rola na horizontal, exceto segmented controls longos (rolagem interna).
- Player no mobile: largura total até `62vh × 9/16`. Approve / Request changes dividem a largura.
- O fluxo inteiro foi desenhado pra 390 px; nenhuma ação existe só no desktop.

## 7. Idioma
No produto, a interface abre em inglês por padrão, com seletor EN/PT no header e em Settings. O **mockup** abre em PT-BR, porque o Gusta pediu pra aprovar em português (05/10). O seletor troca todas as telas, estados, toasts e dados de exemplo entre EN e PT; isso não muda o padrão do produto. Vocabulário PT adotado: Início, Ofertas, Biblioteca, Configurações, Novo criativo, Esperando você, Roteiros, Motor, Geração, Edição, OK final, Aprovar, Pedir ajustes. Kling 3.0, Seedance e lipsync ficam com o nome original. Use i18n por chave desde o início (`next-intl`). O conteúdo gerado segue o idioma da oferta, que aparece no trilho ("Orbit Budget · English").

## 8. O que o frontend precisa da API por tela
| Tela | Leitura | Escrita / ação | Tempo real |
|---|---|---|---|
| Home | `GET /creatives?filter=` → id, nome, oferta, `step`, `status` (`progress/waiting/failed/approved/draft`), `statusLabel`, `progress%`, motor, `updatedAt`, autor, URL da miniatura | — | polling 5 s ou SSE dos criativos em andamento |
| Offers | `GET /offers`, `GET /offers/:id` (campos do brief + `language` + nº de criativos/vencedores) | `POST /offers/extract {url}` → job; `PUT /offers/:id` | status do job de extração (etapas + campos) |
| Offer (wizard) | o mesmo de cima | `POST /creatives {offerId}` → id | — |
| Scripts | `GET /creatives/:id/scripts` → id, ângulo, duração, blocos `{label,start,end,text}`, `winnersUsed[]` | `POST …/scripts:generate {count}`, `POST …/scripts/:sid:regenerate`, `PATCH …/scripts/:sid`, `POST …/scripts/:sid:select` | stream de texto (SSE) por roteiro + etapa atual; resultado parcial com erro |
| Avatar | `GET …/faces` → 4 URLs + status | `POST …/faces:generate {description}`, `POST …/faces/:fid:select` | progresso por rosto, erro com motivo |
| Engine | `GET …/estimate?engine=&model=&format=` → custo, tempo, `sceneCount` (nos dois motores; lipsync = 1 clipe por bloco); vozes (`GET /voices`, com sample); gasto do mês + teto | `POST …/generate {engine, model, voiceId, format}` | — |
| Generation | `GET …/scenes` → n, label, timecode, fala, prompt, status (`queued/generating/ready/failed`), %, motivo da falha, URL do clipe | `POST …/scenes/:n:regenerate {prompt?}` | webhook WaveSpeed → SSE pro front; ETA |
| Edit | `GET …/edit` → template, opções, URL da última prévia, `renderedAt`, `dirty` | `PATCH …/edit`, `POST …/render` | progresso do render (%, frame, total, etapa) e erro com frame |
| Final OK | criativo completo + URL final + custo real | `POST …/approve`; `POST …/changes {type, scene?, line?, note?}` → volta pra etapa | — |
| Library | `GET /library?offerId=&winners=` | `POST /library/:id/winner` (toggle) | — |
| Settings | workspace, membros, serviços (mascarados), gasto | `PATCH /workspace`, `POST /invites` | — |

Regras pro back que a UI assume: todo job longo tem `stage` legível + `%` + `eta`; erro sempre vem com `reason` humano e com a ação sugerida; o estado é salvo a cada etapa (dá pra sair e voltar). Regerar uma cena não invalida as outras.

## 10. Regras adicionadas na validação da F2 (05/10)
Detalhe e motivo em `validacao-f2-2026-10-05.md`.
- **Descarte de trabalho gerado:** sempre `AlertDialog`. Cancelar = "Manter como está" (foco inicial); confirmar = "Descartar e refazer" em `destructive`. O corpo diz o que se perde (cenas, renders, US$ já gastos) e, se a API mandar, quanto custa refazer. Disparado pelo erro `CONFIRM_DOWNSTREAM_RESET`.
- **Cena que falhou:** motivo antes do prompt. "Editar prompt" abre o campo inline, com as ações embaixo: "Refazer com este prompt" + "Cancelar". O botão lateral some durante a edição.
- **Pedir ajustes:** cada caminho mostra o custo e o tempo do retrabalho ("Cerca de US$ 0,95 · 3 min" / "Sem custo"). "Reescrever uma fala" leva pra **Geração** (não pra Roteiros): a fala nova é escrita no painel e só a cena dela regera.
- **Oferta travada:** num criativo já criado, a etapa Oferta mostra só a oferta escolhida, em leitura, com cadeado + "Criar outro criativo com outra oferta". Nada de lista desabilitada.
- **Login:** email + senha, erro em `Alert`, sem recuperar senha na v1; a dica de mock só aparece em dev.
- **Conta:** `DropdownMenu` no avatar com nome, email, Configurações e Sair.
- **Convite:** `Dialog` alinhado à esquerda; gera o link (expira em 7 dias) com o botão Copiar. Email ainda não é enviado.
- **Idioma do briefing:** `Select`, com o valor detectado na página.
- **Segmented que rola:** degradê na borda enquanto houver conteúdo escondido.
